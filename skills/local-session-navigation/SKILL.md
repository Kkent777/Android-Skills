# Android 身份、会话与导航

## 先还原身份链路

先确认是否需要账号。无账号应用仅处理其导航与数据作用域，不增加登录。需要账号时，沿输入 -> 认证 -> session -> 导航 -> 页面查询追踪同一身份；沿用 Compose Navigation、Fragment 或其他既有导航方式。

读取真实认证仓库和会话存取。数据源失败不能当作“用户不存在”；身份已统一到某个仓库时只追踪权威来源，不为套用示例新增 CSV 来源。

## 认证与会话的契约

1. 分清本地账号、服务端 session/token、外部身份提供方和访客。UI 保存的 accountId 不是服务端授权凭证；服务端必须按其认证协议验证访问。
2. 仅在真实存在多来源身份时决定覆盖关系、重复标识与密码失败行为。主来源匹配身份但认证失败时，不未经契约允许用第二来源绕过。
3. 注册与登录采用一致的标识规范化规则；不要单边 trim 密码或静默改旧凭据。需要账号认领时区分未初始化凭据与正常登录；现有本地明文凭据不作为新项目模板。
4. token 等敏感信息沿项目安全存储与刷新契约处理，不把凭据写入日志或 UI state。401/失效与暂时网络故障分别处理，必要的刷新请求避免并发重复。
5. 认证通过后保存真实身份与有效会话，再通知导航层。显示名不是关联键；恢复时检查本地身份是否存在，远端身份按 token/session 有效性处理。

新记录 ID 沿用数据库、服务端或项目既有生成方式。只在明确采用单写入顺序 ID 的旧系统中扫描现有值，不把“最大值加一”作为通用并发身份方案。

## 会话与返回栈一起修复

| 路径 | 需要成立的条件 |
| --- | --- |
| 无 session 冷启动 | 进入未登录区域 |
| session 恢复中 | 保持待定/加载状态，不先当作无 session 跳转后又重建导航 |
| 有效 session 冷启动 | 身份校验后进入受保护区域 |
| 无效 session | 清理失效会话或走现有失效处理，不加载其它用户数据 |
| 登录成功 | 新页面使用已保存的 ID；按需求移除认证页面 |
| 退出 | 清除 session，并移除旧用户的受保护返回路径 |

先画真实 back stack，再选退出清栈目标。Compose Navigation 的 findStartDestination 可能指向受保护起点，不能固定当作欢迎页；launchSingleTop 也不等于清栈。Fragment 等其他导航采用对应栈 API，不为小修复更换框架。

深链和通知入口也检查认证与权限，不能只保护首页按钮。需要登录后恢复原目标时，验证目标参数及数据访问权限，不把未验证的任意路由直接重放。

退出不删除账户或业务记录。用户切换后，页面缓存、表单草稿和数据过滤都必须使用新的身份；提交时捕获身份和输入，保存时校验会话仍适用，不能把旧草稿重新标为新用户记录。

检查晚到的异步结果：A 的登录/列表请求在 logout 或切换 B 后完成时，不应重建 A 的 session 或覆盖 B 的界面。复用现有取消机制或会话版本检查；单靠查询的 accountId 过滤不能阻止过期响应覆盖状态。

## 验证关键路径

1. 无 session -> 登录 -> Home -> Back：不能退回不该保留的认证页。
2. 登录后重启 -> Home；同时验证 ID 非空但用户已不存在的情况。
3. 有效 session 冷启动 -> 退出 -> Welcome -> 再登录 -> Home -> Back；这是动态 startDestination 易漏的路径。
4. 退出后按 Back，不能回到旧 Home，业务记录仍保留；仅在双来源实际存在时分别验证 CSV 用户与本地用户，单来源验证该来源的有效账号。
5. A 新增记录 -> 切换 B -> 再切回 A，确认展示、勾选、草稿和计数不串号；延迟 A 的加载或登录响应到 B 登录后再完成，确认不会回滚当前身份。

交付按“身份来源规则、session 变更、返回栈变更、实际测试路径”说明。编译结果不能替代重启、退出和系统 Back 的行为证据。
