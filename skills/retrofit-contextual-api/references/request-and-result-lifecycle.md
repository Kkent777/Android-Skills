# 请求与结果生命周期场景

以下为新编通用示例，用于检查网络数据流，未调用真实服务。

## 商品或图书查询

- 按实际 API 定义商品 ID、书名等 search 参数，不假定服务支持某种搜索字段。
- 明确无结果才按服务约定回退；400、401/403、429 与 5xx 分别映射输入、认证、限流与服务故障。
- @Query 处理 URL 编码，服务自己的搜索语法仍需校验/转义。
- 缺少可选价格/描述字段可以有 UI 占位，关键记录 ID 缺失则不应造一条有效记录。

## 内容搜索与分页

用户搜 A 后立即搜 B；A 的晚响应不能覆盖 B，旧分页 cursor 也不能混到 B。按服务的 next cursor/末页契约合并并去重，不靠列表长度猜测所有分页规则。

取消请求后传播 CancellationException；旧请求结束不能把新请求的 loading 清掉。重组不能重新发同一请求。

## 创建订单或上传记录

POST 超时可能发生在服务端提交之后，此时结果未知；依据服务的幂等键、业务请求 ID 或查询状态确认。不能认为超时必然失败并无条件重复创建。

服务端成功但缓存写入失败应单独显示/处理，优先重新同步缓存。数据库事务不要跨越长网络请求。

## 可选的笔记摘要服务

只有产品确实要求摘要功能时才接入生成服务。捕获原笔记和作用域版本、发送最少所需文本，把用户内容与指令分隔；输出按格式校验。

生成成功但历史保存失败时保留可重试保存的结果，避免重新生成。要求三条建议时验证三条结构化条目，不能仅截取前三行。

## 凭据与验证

本地开发配置与 APK 内可提取值分清；不把 BuildConfig 当加密保险箱。请求替身使用假 key，禁止真实凭据进入日志或快照。

测试空输入、正常响应、缺字段、畸形 JSON、HTTP 错误、取消、竞态、分页、作用域切换、结果未知与缓存失败；真实联网或计费操作只在任务授权范围内执行。
