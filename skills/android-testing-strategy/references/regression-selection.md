# 测试选择与验收场景

以下为通用设计示例，不是已执行的 Android 测试结果。

## 搜索列表

- 假数据源控制 A、B 请求完成顺序，验证 B 先返回后 A 不覆盖界面。
- 分别覆盖空列表、网络失败、畸形内容与取消；取消不应被显示为普通网络错误。
- 状态测试确认结果，UI 行为测试确认错误可见且可以重试。截图只验证对应状态的布局。

## 笔记保存

让 Repository 写入失败，确认草稿保留、没有成功导航；成功时验证记录属于原项目并触发正确刷新。

保存途中再次编辑或切换工作区，分别确定旧提交是否继续执行，以及成功事件是否仍适用于当前界面。只验证 Snackbar 不足以证明存储正确。

## Room 升级

准备目标支持的旧版本数据库，插入有代表性的父子记录，再升级验证字段、数量、外键与查询。另测空库；内存库不替代文件库重启。

迁移回归不要通过删除数据库、卸载或改成 destructive migration 消除失败。

## Compose 与 Views

沿现有测试工具使用语义或 View 标识驱动实际动作。尺寸/主题/字体样本按受支持范围选取；旋转状态恢复与进程恢复属于不同场景，不互相替代。

## 权限与通知

选择对应 Android 版本与设备能力，覆盖首次请求、拒绝、撤销和从通知进入。宿主层可以测状态机，但系统弹窗和授权行为需要平台证据。

## 推荐的最小结果表

| 项目 | 应记录 |
| --- | --- |
| 测试对象 | 模块、变体、功能/行为合同 |
| 环境 | JVM 或设备/系统；替身与真实组件边界 |
| 执行 | 实际命令、结果、失败输入与报告位置 |
| 未验证 | 环境缺失或本次范围外的用户路径 |
