# Compose 状态与事件场景

以下是新编的跨应用设计示例，用于选择实现和检查点，不代表这些示例已经在设备运行通过。

## 笔记表单：编辑、保存与返回

- 标题、正文由页面已有状态持有者管理；工具栏菜单展开是局部 UI 状态，笔记记录存储属于数据层。
- 保存时捕获笔记 ID、当前草稿与工作区，成功后按导航事件返回；失败保留草稿。
- 列表若观察数据库 Flow，应由查询更新；单次查询则在返回或保存后显式刷新。不要同时维护两份“最新笔记”列表。
- 保存期间允许继续编辑时，旧提交成功不能清空后来输入的文字。用既有草稿版本或请求标识核对完成事件。

## 零售应用：数量、购物车和列表身份

- 数量的最小值、库存上限来自产品契约，不能把所有数字字段都固定为正整数。
- 列表行使用商品/规格稳定 ID；排序或分页后，不能把某行的勾选/展开状态分配给另一个商品。
- 购物车保存在本地还是服务端由业务决定；rememberSaveable 只能恢复可保存 UI 值，不能证明订单已保存。

## 日程应用：日期与时间

- Material DatePicker 的毫秒值表示 UTC 日期起点；日期字段用该日期语义，不先转设备时区导致前一天。
- “某日”与“某个时区的具体时刻”分开建模；日程通知按产品约定处理时区和夏令时。
- 对话框确认才提交草稿，取消保留旧值，Clear 同时处理下次打开的初始值。

## 媒体或搜索页面：加载和过期结果

- 用户快速搜索 A 再搜索 B，A 晚到时不能覆盖 B。
- 错误、空结果与加载分别显示；刷新中的旧数据是否继续展示由页面契约决定。
- ViewModel 通常跨配置变化保留，但不保证进程终止后仍在；需要恢复的查询条件按既有 SavedStateHandle 等机制处理。

## 手动验证

重复点击保存、保存失败、旋转、进程恢复、字体放大、键盘遮挡、列表重排、切换工作区与晚响应；记录真实结果，不以成功 Snackbar 代替持久化证据。
