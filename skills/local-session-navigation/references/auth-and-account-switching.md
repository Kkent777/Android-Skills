# 认证、会话与账号切换场景

以下为通用设计示例，不代表某种认证产品已经在本资料包实现。

## 无账号工具

单位换算器或本地计时器可能完全不需要账号。只处理返回栈、设置与必要状态恢复；不能为了应用导航 skill 自动增加登录。

## 本地笔记账号

- 保存的本地 accountId 只用于找回记录，不是远端认证凭证。
- 启动恢复保持 loading，身份存在后进入用户区域；读取失败与身份被删除分别处理。
- 退出后清会话与受保护返回路径，保留笔记；再用另一个账号进入时，列表、草稿和晚到结果不串号。
- 本地密码验证若为旧系统限制，明确其边界；新产品不把明文密码存储作为默认做法。

## 联网内容应用

- 区分 access token、刷新凭据和用于显示/索引的 accountId，沿服务端协议校验会话。
- 401 不等于网络中断；刷新流程避免多个请求同时刷新以及退出后旧刷新重新登录。
- 退出时是否撤销远端 session 按协议处理，不能只删除客户端标志就声称服务端会话失效。
- 本地按 accountId 过滤不是服务器授权检查的替代；远端应校验调用者访问目标资源的权限。

## 深链与通知

未登录时打开订单详情链接，先完成认证再恢复已验证目标。参数格式检查不等于资源授权；登录后还要确认该账号可以访问订单。

导航框架保留已有方案。Compose 使用 graph/route 的栈 API，Fragment 使用其导航栈；不能仅凭 launchSingleTop 声称旧受保护页面已清除。

## 验证路径

无 session 冷启动、有效/失效 session、离线恢复、会话恢复中深链、退出后系统 Back、A 请求晚于 B 登录返回、刷新中退出和跨账号草稿隔离。
