# 性能证据与复测模板

本模板只说明应记录什么，没有预设性能分数、目标阈值或已测结果。

## 基线表

| 字段 | 记录内容 |
| --- | --- |
| 场景 | 明确动作，例如固定内容列表滚动或冷启动 |
| 版本 | 源码版本/工作区状态、模块、变体与优化配置 |
| 环境 | 设备、系统、数据规模、工具、负载和温度等已知条件 |
| 测量 | 指标定义、次数、采样设置与原始报告位置 |
| 结果 | 实际分布/统计方式，不填猜测值 |
| 限制 | 不可比条件、设备缺失或未复现路径 |

## 例：重组很多但没有卡顿证据

先确定场景与帧指标，再定位有成本的工作；高重组次数不能单独证明卡顿。不要全项目加稳定性标注或换集合来降低计数。

## 例：一次滚动发现主线程重解析

由 trace 或采样关联到具体解析工作后，修改其职责/执行时机，并检查列表更新与取消行为。使用同一数据量和构建重新测量；不同缓存状态的结果不能直接比较。

## 例：删 keep 规则后包体下降

核对规则来源与实际依赖，测试 release 中的反射、导航、序列化和相关功能。包变小但关键路径崩溃不算优化成功。

## 例：只有静态代码，没有设备

可以记录“疑似主线程阻塞”“规则范围过宽待验证”，列出需要的测量；不填改善百分比，不声称用户体验已提升。

## 最终记录

按“问题 -> 证据 -> 原因/假设 -> 小范围修改 -> 同条件复测 -> 功能回归 -> 未验证项”报告。原始 trace 与敏感数据按任务约定保存，不放入可公开技能示例。
