# Retrofit 请求、上下文与结果保存

## 先追踪一次真实请求

沿界面事件 -> ViewModel/既有状态层 -> Repository -> Retrofit service 跟踪 base URL、endpoint、HTTP 方法、header、query/body、响应 model 和最终 UI state。缓存或历史保存再追踪本地数据层；Compose 或 View 页面均不直接发起业务 HTTP 请求。

从目标仓库的依赖和现有实现确认服务契约；需要核实远端模型可用性或新版 API 时查服务方当前文档，不把历史模型名当作永久有效值。诊断可先用本地样例或测试替身；不会因读取 skill 自动调用付费生成服务。

## 请求与映射

1. 区分读取、创建、更新、删除与生成请求的语义，复用已有 Retrofit/provider 与配置入口，不复制认证或 key 管理代码。
2. 验证 base URL 与相对 endpoint 拼接、参数位置、JSON 层级和字段名。用 typed models 与已有 converter，缺字段按可空契约处理。
3. 多策略查询只在明确无结果时回退，例如按服务契约从商品编号改为关键词查询；超时、认证失败、限流或服务端错误不能被当成“没搜到”。分页 API 另外明确 cursor、末页和重复项处理，重搜时重置旧分页状态。
4. `@Query` 负责 URL 参数编码；输入里的引号等搜索语法字符仍需按服务契约处理，不能把 URL 编码当作查询语法转义，也不要重复编码。
5. 数组、空数组、null、空白和有效文本分开映射。面向 UI 的缺失占位文案由展示契约决定，不能把占位文本当成功生成结果入库。

## 错误与协程

| 情况 | 处理 |
| --- | --- |
| 空输入或缺配置 | 发请求前返回字段/配置错误 |
| 400/字段校验错误 | 映射有效的输入反馈；不自动改成无结果或盲目重试 |
| 服务约定的 404/空结果 | 明确无结果，可按约定回退搜索 |
| IOException/连接失败 | 连接提示与重试入口 |
| 401/403、429、5xx | 分别处理认证、限流和服务不可用，不统一成无结果 |
| JSON 不匹配或响应缺有效内容 | 协议/空响应错误；不保存假结果 |
| CancellationException | 原样抛出，不能落入普通失败提示 |

使用项目现有 sealed result / error state；没有必要为小修复重建全局错误框架。读外部 error body 时做长度和敏感内容控制，不直接把完整服务错误、请求 header 或 key 回显给 UI/log。

Retrofit suspend 调用与 Room suspend DAO 支持异步执行；`launch` 本身不保证后台线程。阻塞文件操作、同步解析等按其实际成本和现有 dispatcher 安排。加载标志要在成功、失败和取消路径结束时恢复，且旧请求不能清掉新请求的 loading。

## 作用域归属与写入结果

- 请求开始时捕获实际业务作用域，如账号、项目或搜索条件。响应绑定原请求，不在返回时换成新 session；无账号公开查询不强加 userId，过期结果不覆盖新界面。
- 远端写入区分成功、失败与结果未知。超时后服务可能已提交，不能直接认定失败并再次创建；按接口幂等键或查询确认机制处理。网络请求不放在长时间数据库事务里。
- 缓存与服务端数据明确哪方权威、过期条件和离线行为；本地缓存失败不应自动重复已成功的远端业务操作。

## 仅在功能需要生成服务时

- 使用最少必要上下文，区分个人内容与汇总统计，敏感数据沿产品授权和传输约定处理。
- 指令与笔记、商品名等输入数据分隔，明确输出格式、长度与该领域适用限制；指令本身不构成可靠性保证。
- 需要固定条数或结构时校验响应，`.take(3)` 不保证恰好三条，不把任意换行当新条目。
- 外部请求完成后验证有效内容，再按产品要求保存到既有数据层；不让数据库事务跨越整个网络请求。历史按真实账号/项目等作用域查询，无账号应用不增加虚构用户，排序使用明确时间/ID。
- 区分“生成失败”和“生成成功但历史保存失败”。后者优先重试保存已有结果，避免再次付费生成或插入重复历史；采用现有稳定请求/记录身份，不无条件新增架构。

## 配置与验证

配置入口可用 local.properties -> BuildConfig 或现有安全方案，不打印实际值。BuildConfig 将值打入客户端，不能称为不可提取的秘密；生产部署按项目约定使用后端或受限凭据，不把整套后端作为小修复的额外范围。

按改动检查：空输入、正常结果、策略回退、缺字段、畸形 JSON、401/403、429、5xx、超时、取消、快速重搜、用户切换、保存失败和历史过滤。使用请求替身验证 JSON/header 时只用假 key，不做真实 key 快照。编译通过不能替代实际 API 或设备验证。

需要请求竞态、分页、结果未知或保存重试的例子时，读取 [请求与结果生命周期](references/request-and-result-lifecycle.md)。普通联网功能不要求接入生成服务。
