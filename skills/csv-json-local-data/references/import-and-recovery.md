# 文件导入、序列化与恢复场景

以下为通用设计示例，不是从其他应用取得的运行证据。

## 商品目录 CSV

示例列为 item_id、title、price、group_id；项目应以自己的真实数据契约为准。

- 核对 UTF-8/BOM、引号内逗号、双引号转义、尾空字段和字段内换行。
- 标题可为空与主键缺失是不同问题；group_id 是关联字段时要核对父记录。
- itemid 和 item_id 是否互为别名由导入契约决定，规范化后重复 header 不能静默覆盖。
- 有效空文件、读取失败、单行被拒绝和整体 schema 不符要可区分；批次导入部分成功还是全部回滚也需明确。
- 文件通过系统 picker 提供时使用获得的 URI 和授权，不假定可直接读取某个磁盘路径。

## JSON 收藏列表损坏

原应用若已用 preferences 保存 JSON，区分缺 key、空数组、JSON null、类型错误和损坏内容。恢复时保留原值，不执行“读失败返回空列表 -> 新增一项 -> 覆盖旧值”。

泛型数组需要正确的元素类型；可解析成对象还需检查记录 ID 与业务必要字段。使用 kotlinx.serialization 的项目无需为此换成 Gson。

## 多账号或多工作区追加

共享列表写入时保留其它作用域记录，显示时才过滤。单进程某个 helper 的锁不保护其它实例或跨进程写入；发现并发丢更新时按任务选择单写入入口、事务存储或迁移。

无账号个人工具无需额外造一个 accountId；其数据仍需按文件/项目等真实边界处理。

## 导出

确认目标编码、列顺序、日期和金额格式，文本按 CSV 方言转义。打开到电子表格的导出若含用户文本，按交付场景处理公式执行风险；不破坏用于程序往返的原始数据契约。

## 验证

使用无敏感信息的 fixture 覆盖正常往返、坏记录、重复 ID、失败不覆盖、跨作用域追加与导出重导入；磁盘持久化另用重启验证。
