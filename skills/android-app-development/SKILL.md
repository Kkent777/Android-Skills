# Android 应用开发

## 先确定产品与工程约束

读取适用的 AGENTS.md、目标模块、Gradle/version catalog、Manifest、关键入口和已有测试。区分新工程与已有工程，确认使用场景、关键用户动作、数据来源、支持设备和验收方式；只补问无法从工程判断且会改变实现的要求。

按产品实际决定功能：工具、笔记、内容、零售、日程、媒体或设备控制应用可以有完全不同的数据和身份模型。没有账号需求就不加登录；不需要持久数据就不引入数据库；离线功能无需自动增加网络或生成服务。

新工程按需求选择 Kotlin/Compose 或既定技术栈；已有 View/XML、Fragment、Java、Compose 混合项目沿用原约定，只在任务明确要求时迁移。此包适用于原生 Android 工作；跨平台项目涉及共享层时先识别其框架边界。

## 将需求落到数据流和状态寿命

画出本次用户动作的最短路径：界面 -> 状态/事件处理 -> 业务或数据层 -> 存储/系统/服务。复用现有 MVVM、MVI 或分层方式，不为单点修改引入全新架构。

- 界面瞬时状态、配置变化恢复、进程恢复和持久业务记录分别处理；ViewModel 不保证进程退出后仍有状态。
- Repository 在需要隔离数据来源、协调规则时使用；不为无数据访问的纯展示组件机械增加 Repository/DAO。
- 区分用户、工作区、项目等访问范围。无账号应用按本地模型处理，不能从例子强加 userId。
- 按依赖顺序实现可用闭环，检查空数据、加载、失败、取消、重复操作和返回路径。

## 平台能力按任务验证

| 涉及能力 | 必须查清的边界 |
| --- | --- |
| 生命周期与导航 | 旋转、进程恢复、前后台、系统 Back、深链/通知入口；重建不能重复执行业务动作 |
| 权限与外部文件 | 当前 SDK 的 Manifest/运行时权限、拒绝与撤销、系统 picker、URI 授权和作用域存储；只请求必要权限 |
| 相机、定位、蓝牙、传感器 | 设备支持、权限、生命周期注册/释放与失败降级；模拟器结果不替代相关真机能力 |
| 后台任务与通知 | 延迟可恢复任务、精确时间和持续前台任务分别选择合适系统机制；核对执行限制和通知入口 |
| 音视频与大列表 | 资源释放、缓存/分页、后台行为、内存与帧率；先测量实际瓶颈 |
| 支付、身份或推送 SDK | 供应方当前 SDK 契约、回调幂等、测试环境、凭据边界与服务端校验；不由本地成功提示推断交易成功 |
| 自适应与可访问性 | 字体缩放、窄屏/横屏/大屏、触控目标、语义、读屏和键盘；关键操作始终可达 |

涉及版本变化的系统规则或第三方 SDK，按项目实际版本核对当前官方资料。表中的检查点不等于这些 SDK 已提供完整模板，也不预先授权付费调用、发布或外部交易。

## 验证与交付

从 Gradle 任务与模块发现实际命令，不假定所有工程都叫 app 或只有 debug。根据改动运行编译、相关单元/仪器测试、Lint 和适当变体打包；不为纯文案变动无条件跑所有设备测试。

先盘点现有测试/分析能力，再按具体风险选层级；新工具的任务、API 与插件按当前版本验证，不为得到某个功能自动升级整个工程。截图、行为测试和性能指标回答不同问题，不能互相充当通过证据。

用户路径验证覆盖核心动作和失败恢复；权限、后台、计费和硬件相关路径需对应环境证据。发布任务再检查 applicationId、版本、签名配置、混淆、目标变体与产物，不展示私钥或密码。

交付说明实现位置、选择依据、实际完成的验证与缺失环境。编译、打包、安装、运行和外部服务成功分别报告。
